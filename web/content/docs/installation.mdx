## Requirements

- **macOS** (Linux works for the CLI; the floating panes need Rex).
- **[Rex](https://www.superlogical.com/rex)**, the terminal Axel lives in. Outside Rex, Axel
  runs the same interface inline in your terminal.
- **A harness**, installed and logged in: [Claude Code](https://claude.ai/code),
  [Codex](https://openai.com/codex), [OpenCode](https://opencode.ai), or one of the
  [others](#harnesses).

## Install Axel

```bash
curl -fsSL https://axel.md/install | sh
axel
```

The script downloads the latest release for your Mac, checks its sha256 and puts `axel` in
`~/.local/bin` (set `AXEL_INSTALL_DIR` to choose another place). Every commit on `main`
that passes CI is released; run it again to update, or pass a version:
`curl -fsSL https://axel.md/install | sh -s -- 0.3.80`.

### With Homebrew

```bash
brew install scarce/taps/axel
```

`brew upgrade` then brings the newest build. Use the full name: Homebrew core has an
unrelated `axel`.

### From source

With Rust and [`just`](https://github.com/casey/just):

```bash
git clone https://github.com/scarce/axel && cd axel
just install    # release build, linked into ~/.local/bin and ~/.cargo/bin
```

`~/.local/bin` usually comes before Homebrew on your `PATH`, so a source build wins over
the Homebrew one until you remove `~/.local/bin/axel`.

## First run

The first time, `axel` runs **`axel setup`** before anything else:

- it checks this machine: Rex, git, and which harnesses and
  ACP adapters are installed, and offers to install a missing adapter;
- it creates your first agent: a name, its harness, a few skills, a colour and a runtime
  mode;
- for Claude Code on autopilot, it offers to accept Claude Code's one-time bypass prompt;
- then it opens the launcher.

It also creates your **owner key** (an Ed25519 key kept in the macOS keychain) and the local
database at `~/.axel/axel.db`. Run `axel setup` again any time to add another agent, and
`axel doctor` to check everything is in order.

## Managed sessions (recommended)

Axel drives agents best over the [Agent Client Protocol](https://agentclientprotocol.com):
you then work in Axel's own thread view, and permissions are decided by your policies
rather than by a dialog in some pane.

- **Claude Code:** nothing to install. Axel's adapter is built in and drives the `claude`
  CLI directly; no Node or npm needed.
- **Codex:** nothing to install either. Axel's adapter drives your `codex` through
  `codex app-server`, so it always runs your Codex version, config and login.
- **OpenCode:** ACP is built into OpenCode itself (`opencode acp`).
- **The others** speak ACP themselves, or through an adapter you install next to them.

## Harnesses

| Harness | Name | Axel runs | Install |
|---|---|---|---|
| Claude Code | `claude` | built-in adapter | `curl -fsSL https://claude.ai/install.sh \| bash` |
| Codex | `codex` | built-in adapter | `npm i -g @openai/codex` |
| OpenCode | `opencode` | `opencode acp` | `npm i -g opencode-ai` |
| Goose | `goose` | `goose acp` | [goose-docs.ai](https://goose-docs.ai/docs/getting-started/installation/) |
| Cursor | `cursor` | `cursor-agent acp` | `curl https://cursor.com/install -fsS \| bash` |
| Pi | `pi` | `pi-acp` | `npm i -g @earendil-works/pi-coding-agent pi-acp` |
| Oh My Pi | `omp` | `omp acp` | [omp.sh](https://omp.sh) |
| Devin | `devin` | `devin acp` | [docs.devin.ai/cli](https://docs.devin.ai/cli) |
| Grok Build | `grok` | `grok agent stdio` | [docs.x.ai](https://docs.x.ai/build/overview) |
| Kimi Code | `kimi` | `kimi acp` | [kimi.ai](https://kimi.ai/download) |
| Amp | `amp` | `amp-acp` | `npm i -g @sourcegraph/amp amp-acp` |
| Hermes Agent | `hermes` | `hermes-acp` | [hermes-agent.nousresearch.com](https://hermes-agent.nousresearch.com) |
| OpenClaw | `openclaw` | `openclaw acp` | [docs.openclaw.ai](https://docs.openclaw.ai/start/getting-started) |

Name it when you create an agent, with its model after a `/` if you like:
`axel agent new gus goose`, `axel agent new opus claude/opus`. `AXEL_ACP_<NAME>` replaces the
command Axel runs (`AXEL_ACP_PI="npx pi-acp"`). Skills are installed for Claude Code, Codex
and OpenCode; the others get your `AXEL.md` in their prompt.

Without an adapter, an agent runs as its normal CLI in a Rex pane, and reports its status
through hooks that Axel installs at launch.

## A key binding

Bind Axel to a key in Rex: append
[`docs/rex-init.lua`](https://github.com/lgalabru/axel/blob/main/docs/rex-init.lua) to
`~/.config/rex/init.lua`, then run `rex config reload`.

## Claude Code's autopilot prompt

Agents run on **autopilot** by default: Claude Code starts with bypass permissions, and
Axel's guard hook still refuses irreversible shell commands. Claude Code asks you to accept
that mode once per machine. Accept it the first time, or set it ahead of time in
`~/.claude/settings.json`:

```json
{ "skipDangerousModePermissionPrompt": true }
```

See [Permissions and budgets](/docs/policies) for the other modes.
