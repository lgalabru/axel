title: Command line
description: Every axel command. `axel <command> --help` has the flags.
---

`axel` with no arguments opens the launcher (inside Rex, as floating panes; elsewhere,
inline). Run it again to close it. The first time, with no agent yet, it runs `axel setup`
first. Everything else is a subcommand.

Commands answer to the names you'd reach for: the plurals (`axel threads`, `sessions`,
`agents`, `hosts`, `logs`), `list` for `ls`, `info` for `show`, `create` for `new` (and
`add` for agents, `start` for threads), `rm` for `thread delete`, `settle` for `thread
done`, and `msg` for `send`.

## Updates

`axel update` runs `curl -fsSL https://axel.md/install | sh`, with installer output
shown directly. The composer suggests it when a background check finds a release
more than ten patches ahead, or at least one minor or major version ahead.

## Agents

| | |
|---|---|
| `axel agent new NAME [HARNESS[/MODEL]] [--skills a,b\|*] [--color C] [--runtime-mode M] [--host H]` | Create an agent: key, attestation, profile. `terra codex`, `opus claude/opus`, `gus goose`. |
| `axel agent edit NAME [HARNESS[/MODEL]] [--model M] [--name NEW] [--skills a,b\|*] [--prompt P] [--color C] [--allow A] [--disallow A] [--reach nobody\|anyone] [--daily-usd N\|unlimited] [--max-depth N] [--runtime-mode M] [--host H\|local]` | Change anything about it: harness, model, name, skills, prompt, colour, permissions, budget, mode or default host. A rename keeps its key and history; running sessions keep the old name until they restart. |
| `axel agent ls` · `show NAME` · `archive NAME` | List, inspect, retire. |

## Skills

| | |
|---|---|
| `axel skills ls` | Every skill this project can use, and where each comes from. |
| `axel skills update [SOURCE] [--yes]` | Fetch remote skills, show what changed, move their pins in `AXEL.lock`. |

See [The AXEL.md file](/docs/axel-md).

## Threads

| | |
|---|---|
| `axel thread new "intent" --agent NAME [--project DIR]… [--scratch] [--worktree [BRANCH]] [--host H] [--no-launch]` | A thread and its first session. |
| `axel thread spawn THREAD --agent NAME [--host H]` | Another agent on the same thread. |
| `axel thread resume THREAD [--agent NAME]` | A new session continuing the last harness conversation. |
| `axel thread attach THREAD --project DIR` | Attach another project. |
| `axel thread open THREAD` | The thread view, in this terminal. |
| `axel thread split THREAD` | A Rex window: the conversation above, the composer below. |
| `axel thread ls [--all]` · `show THREAD` | List, inspect. |
| `axel thread manage THREAD` | The thread controls: its sessions and spend, and reset, move, settle, archive, stop, rename. **Ctrl+D** in the composer opens the same. |
| `axel thread diff THREAD [--session S] [--turn N] [--stat]` | What a turn changed: the file list, then the patch. Without `--turn`, the latest turn that changed a file. `--pane` is the floating pane a change line opens. |
| `axel thread undo THREAD [--session S] [--turn N] [--restore] [-y]` | Take a turn's edits back out of the working tree, keeping later work unless it overlaps; `--restore` rewrites the turn's files to how they were before it. A snapshot is kept first; the agent is told. |
| `axel thread stop THREAD` | End every live session on it. |
| `axel thread done` · `reopen` · `archive` · `delete THREAD` | Settle, reopen, archive, delete. |

Thread and session ids accept any unique prefix.

## Sessions

| | |
|---|---|
| `axel session ls [--all]` | Sessions, with their state and where they run. |
| `axel session stop SESSION` | End one session and close its pane. |
| `axel session move SESSION --to HOST\|local` | Move a running Claude Code session to a host, or home. |
| `axel log SESSION [-f]` | The raw frames of a managed session. |

## Messages and status

| | |
|---|---|
| `axel send "@opus …"` | A signed message to every `@name` in the text, as you, or as `$AXEL_AGENT` from inside a session. |
| `axel inbox [--agent NAME]` | Your inbox, or an agent's. |
| `axel status working\|blocked\|done\|idle\|error\|clear "msg" [--kind permission\|question\|auth]` | Report a status for `$AXEL_THREAD`. |

## Hosts

| | |
|---|---|
| `axel host add TARGET` | Install Axel on a machine reachable over SSH and register it. |
| `axel host ls` · `rm LABEL` | List, forget. |
| `axel sync [HOST] [--follow]` | Exchange threads, conversations and job branches with hosts. Runs by itself while hosts work for you. |

## Plumbing

| | |
|---|---|
| `axel ui [--screen launch\|threads\|dashboard\|inbox]` | What the floating panes run. |
| `axel mcp` | The MCP server, on stdio. |
| `axel hook claude\|codex` | The hook sink; installed for you at launch. |
| `axel setup` | Check this machine and create an agent, interactively. Runs by itself the first time. |
| `axel usage` | The tokens pane in the top-right corner of the Rex window: what each agent spent (last hour, 24 hours, all time), its context fill, and how much of your plan limits is used. Run it again to hide it. See [Tokens and cost](/docs/usage). |
| `axel gc` | Prune old turn checkpoints: archived threads after a week; on live threads, after a month, all but each session's latest 20 turns. Runs by itself after `axel thread archive`. |
| `axel doctor` | Check Rex, the keychain and the database. |
